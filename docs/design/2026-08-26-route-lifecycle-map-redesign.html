01 / ROUTE LIFECYCLE

One shared state machine for Practice and Mock

The visual shell changes slightly for an assessed drive, but start detection, recovery, completion, and confirmation use the same transitions. This removes the current split where Practice shows a completion screen while Mock exits automatically.

01PreviewLive, low-cost position watch starts after permission.
02ApproachRoute to the start and count stable arrival fixes.
03Start pendingPause guidance. Wait for explicit Begin.
04Active routeTrack progress, turns, camera, and scoring.
05RecoveringFetch the safest forward rejoin and rebase.
06Finish pendingLatch candidate time. Wait for explicit End.
07CompletePersist once, release watchers, show result.
02 / DECISION RULES

Confidence is earned across fixes, not inferred from one dot

Accuracy, speed, proximity, and progress are evaluated together. The thresholds retain the current route geometry assumptions while closing the stale-preview and automatic-finish gaps.

05 / MOTION

Motion explains state changes, then gets out of the way

The route itself supplies the signature: the driven section cools to grey while the road ahead stays green. Only arrival and recovery introduce a stronger orchestrated moment.

Camera follow450 ms blended moves. Vehicle remains in the lower third with the next road exposed.
Arrival320 ms bottom-sheet rise, one success haptic, and a restrained start-marker pulse.
Recovery220 ms deck recolor. Route dims once; amber return line moves only to show direction.
Rejoined1.6 s confirmation toast. Green returns before normal guidance resumes.
Scope boundary

This design does not add background navigation, offline road graphs, lane guidance, traffic, or a night theme. It focuses on the route lifecycle, recovery correctness, and a unified professional map surface.
