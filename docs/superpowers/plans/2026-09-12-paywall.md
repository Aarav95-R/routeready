# Paywall Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every test centre gives one route away free; a £3/week or £9/month subscription opens the other nine.

**Architecture:** The gate is enforced by Postgres row-level security, never by the client. `routes.steps` moves into a `route_details` table whose policy admits a row only when the route is free or the caller is subscribed; the `hazards` policy gains the same condition. RevenueCat wraps StoreKit and its webhook writes an `entitlements` row through a Supabase Edge Function. The app reads that state into a zustand store and reflects it — it never decides it.

**Tech Stack:** Expo 54 / React Native 0.81, expo-router, zustand, Supabase (Postgres + Edge Functions on Deno), RevenueCat (`react-native-purchases`), NativeWind, Jest + @testing-library/react-native.

**Spec:** `docs/superpowers/specs/2026-09-12-paywall-design.md`

## Global Constraints

- **Prices:** £3/week, £9/month. Never hard-code these in the app — read them from StoreKit via RevenueCat. The numerals appear in this plan only in seed data, product identifiers and test fixtures.
- **Gated set:** `routes.steps` and `hazards`. Nothing else. `geometry`, `speed_profile`, `observation_zones`, `phases`, `difficulty`, `distance_km`, `estimated_minutes` all stay public — `plainSummary()` derives the card's second line from `speed_profile` and `observation_zones`, and gating either empties the copy that sells the locked card.
- **Never revoke a drive in progress.** Entitlement is read once when a drive starts and never re-checked until it ends.
- **Entitlement statuses are `active | lapsed` in Postgres**, plus `unknown` on the client only. RevenueCat's grace and billing-retry states map to `active`.
- **No emojis anywhere in UI copy.** Segmented controls are flush.
- **Palette:** green (`colors.accent`) is route-and-action; clay (`colors.clay`) is the person and their progress. Never introduce a second green. A locked state is neutral stone, never `colors.danger` — a locked route is not an error.
- **Type:** every `Text` style must carry a face from `FACES` in `src/ui/type.ts`; React Native ignores `fontWeight` when a static family is named.
- **Tests:** `npm test` runs Jest. Screens verify on the iOS simulator, not in Jest — Jest cannot see layout or sheet position.

- [ ] **Step 1: Write the migration**

Create `supabase/migrations/2026-09-12-paywall.sql`:

```sql
-- The paywall: one free route per centre, the rest behind a subscription.
--
-- Safe to re-run.
--
-- The gate is two things and only two: `routes.steps` and a route's `hazards`.
-- Everything else on the row stays public, because the route cards are built
-- from it — `plainSummary` in src/lib/routeSummary.ts derives the card's second
-- line from `speed_profile` and `observation_zones`, so gating either would
-- collapse every locked card to "A steady drive around the area." and blank the
-- thumbnail's pins, while withholding nothing anyone could drive from.
--
-- `steps` moves to a table of its own rather than staying a column, because RLS
-- is row-level: a field that must be withheld has to live in a row. The column
-- is then dropped, not left behind — leaving it means `select("*")` keeps
-- serving the one thing this migration exists to withhold, and the leak would
-- be invisible because the client reads the new table and looks correct.
begin;

-- ── One free route per centre ──────────────────────────────────────────────
alter table routes add column if not exists is_free boolean not null default false;

-- At most one. It cannot enforce *at least* one — a centre with none silently
-- becomes fully paywalled, which is the worse failure — so scripts/check-paywall.ts
-- asserts the other direction.
create unique index if not exists routes_one_free_per_centre
  on routes (centre_id) where is_free;

-- An interim pick so no centre is fully locked between this migration and the
-- next seed run. The seed script chooses deliberately; this only has to be
-- deterministic and present.
update routes set is_free = true
where id in (
  select distinct on (centre_id) id
  from routes
  order by centre_id, difficulty, name
);

-- ── The gated half of a route ──────────────────────────────────────────────
create table if not exists route_details (
  route_id uuid primary key references routes(id) on delete cascade,
  steps jsonb not null default '[]'
);

insert into route_details (route_id, steps)
select id, coalesce(steps, '[]'::jsonb) from routes
on conflict (route_id) do nothing;

-- ── Who has paid ───────────────────────────────────────────────────────────
-- Two statuses, not four. RevenueCat distinguishes grace and billing-retry;
-- this table does not, because the only question it answers is whether to serve
-- the route, and during grace the answer is yes. Two statuses keep the policy a
-- boolean.
create table if not exists entitlements (
  user_id uuid primary key references auth.users(id) on delete cascade,
  status text not null check (status in ('active', 'lapsed')),
  product text,
  renews_at timestamptz,
  updated_at timestamptz not null default now()
);

alter table entitlements enable row level security;

-- Select only. Every write comes from the RevenueCat webhook under the service
-- role, which bypasses RLS; an app that could write this row could grant itself
-- the subscription.
drop policy if exists "Own entitlement" on entitlements;
create policy "Own entitlement" on entitlements
  for select to authenticated
  using (auth.uid() = user_id);

-- security definer so it can read entitlements past that policy. An empty
-- search_path would break the unqualified table name; pinning it to public is
-- what stops a caller-controlled path resolving `entitlements` elsewhere.
create or replace function is_subscribed() returns boolean
  language sql stable security definer set search_path = public
as $$
  select exists (
    select 1 from entitlements
    where user_id = auth.uid() and status = 'active'
  );
$$;

-- ── The policies that do the gating ────────────────────────────────────────
alter table route_details enable row level security;

drop policy if exists "Free or subscribed" on route_details;
create policy "Free or subscribed" on route_details
  for select to anon, authenticated
  using (
    exists (select 1 from routes r where r.id = route_details.route_id and r.is_free)
    or is_subscribed()
  );

drop policy if exists "Public read" on hazards;
drop policy if exists "Free or subscribed" on hazards;
create policy "Free or subscribed" on hazards
  for select to anon, authenticated
  using (
    exists (select 1 from routes r where r.id = hazards.route_id and r.is_free)
    or is_subscribed()
  );

-- Last, and only after the backfill above.
alter table routes drop column if exists steps;

commit;
```

- [ ] **Step 2: Write the policy check script**

Create `scripts/check-paywall.ts`:

```ts
/**
 * Asserts the paywall's server-side half, against the live schema.
 *
 * Jest cannot reach this: the gate is row-level security, which only exists
 * inside Postgres. These checks impersonate a signed-in user the way PostgREST
 * does — `set local role authenticated` plus a `request.jwt.claims` carrying a
 * `sub` — so `auth.uid()` resolves and the policies actually run.
 *
 * Every check runs inside a transaction that is rolled back, so this is safe
 * against a seeded database and writes nothing.
 *
 * Run: npm run check:paywall
 */
import { Client } from "pg";

const CONNECTION = process.env.SUPABASE_DB_URL;

const SUBSCRIBER = "11111111-1111-1111-1111-111111111111";
const FREELOADER = "22222222-2222-2222-2222-222222222222";

let failures = 0;

function check(name: string, ok: boolean, detail = "") {
  if (ok) {
    console.log(`  ok    ${name}`);
  } else {
    failures++;
    console.error(`  FAIL  ${name}${detail ? ` — ${detail}` : ""}`);
  }
}

/** Run `fn` as a signed-in user, then roll everything back. */
async function asUser(c: Client, userId: string, fn: () => Promise<void>) {
  await c.query("begin");
  try {
    await c.query("set local role authenticated");
    await c.query("select set_config('request.jwt.claims', $1, true)", [
      JSON.stringify({ sub: userId, role: "authenticated" }),
    ]);
    await fn();
  } finally {
    await c.query("rollback");
    await c.query("reset role");
  }
}

async function main() {
  if (!CONNECTION) {
    console.error("SUPABASE_DB_URL is not set. See SETUP.md for the pooler URL.");
    process.exit(1);
  }
  const c = new Client({ connectionString: CONNECTION });
  await c.connect();

  // ── Shape ────────────────────────────────────────────────────────────────
  const dropped = await c.query(
    `select 1 from information_schema.columns
      where table_name = 'routes' and column_name = 'steps'`,
  );
  check("routes.steps is dropped", dropped.rowCount === 0,
    "the column still exists, so select('*') still serves it");

  const orphaned = await c.query(
    `select count(*)::int as n from routes r
      left join route_details d on d.route_id = r.id
      where d.route_id is null`,
  );
  check("every route has a details row", orphaned.rows[0].n === 0,
    `${orphaned.rows[0].n} routes have none`);

  const centres = await c.query(
    `select count(*)::int as n from (
       select centre_id from routes group by centre_id
       having count(*) filter (where is_free) <> 1
     ) bad`,
  );
  check("every centre has exactly one free route", centres.rows[0].n === 0,
    `${centres.rows[0].n} centres have none or several`);

  // ── The gate ─────────────────────────────────────────────────────────────
  const { rows: sample } = await c.query(
    `select
       (select id from routes where is_free limit 1) as free_id,
       (select id from routes where not is_free limit 1) as locked_id`,
  );
  const { free_id: freeId, locked_id: lockedId } = sample[0];
  if (!freeId || !lockedId) {
    check("database has both a free and a locked route", false, "seed it first");
  } else {
    await asUser(c, FREELOADER, async () => {
      const free = await c.query("select 1 from route_details where route_id = $1", [freeId]);
      check("unsubscribed reads a free route's steps", free.rowCount === 1);

      const locked = await c.query("select 1 from route_details where route_id = $1", [lockedId]);
      check("unsubscribed is refused a locked route's steps", locked.rowCount === 0,
        "the paywall does not hold");

      const hazards = await c.query("select 1 from hazards where route_id = $1", [lockedId]);
      check("unsubscribed is refused a locked route's hazards", hazards.rowCount === 0);
    });

    await c.query("begin");
    await c.query(
      `insert into entitlements (user_id, status) values ($1, 'active')
         on conflict (user_id) do update set status = 'active'`,
      [SUBSCRIBER],
    );
    await c.query("set local role authenticated");
    await c.query("select set_config('request.jwt.claims', $1, true)", [
      JSON.stringify({ sub: SUBSCRIBER, role: "authenticated" }),
    ]);
    const paidLocked = await c.query("select 1 from route_details where route_id = $1", [lockedId]);
    check("subscriber reads a locked route's steps", paidLocked.rowCount === 1);
    const paidHazards = await c.query("select 1 from hazards where route_id = $1", [lockedId]);
    check("subscriber reads a locked route's hazards", paidHazards.rowCount >= 0);
    await c.query("rollback");
    await c.query("reset role");
  }

  // ── Entitlements are not self-writable ───────────────────────────────────
  await asUser(c, FREELOADER, async () => {
    let refused = false;
    try {
      await c.query("insert into entitlements (user_id, status) values ($1, 'active')", [FREELOADER]);
    } catch {
      refused = true;
    }
    check("a user cannot grant themselves an entitlement", refused,
      "the insert succeeded — anyone can unlock everything");
  });

  await c.end();
  console.log(failures === 0 ? "\npaywall: all checks passed" : `\npaywall: ${failures} failed`);
  process.exit(failures === 0 ? 1 - 1 : 1);
}

main().catch((e) => { console.error(e); process.exit(1); });
```

- [ ] **Step 3: Implement `pickFreeRoute`**

In `scripts/seed/generate.ts`, above the generation loop:

```ts
/**
 * Which of a centre's ten routes is given away.
 *
 * The free route is the demo, so it is chosen rather than fallen into. The
 * easiest route undersells the app — a learner drives a gentle loop, sees
 * nothing they were worried about, and has no reason to pay. The hardest
 * oversells it and reads as a route nobody would practise first. The median is
 * the representative one.
 *
 * Ties break on name so that a reseed does not silently move the free route out
 * from under a learner who has been driving it.
 */
export function pickFreeRoute(routes: { difficulty: number; name: string }[]): number {
  if (routes.length === 0) return -1;
  const ordered = routes
    .map((r, i) => ({ ...r, i }))
    .sort((a, b) => a.difficulty - b.difficulty || a.name.localeCompare(b.name));
  return ordered[Math.floor((ordered.length - 1) / 2)].i;
}
```

- [ ] **Step 4: Update the repo**

Replace `src/services/routesRepo.ts`:

```ts
import { supabase } from "@/lib/supabase";
import type { Hazard, NavStep, Route } from "@/types/db";
import { Cached, cachedFetch } from "./cache";

/**
 * Named rather than `*`, and that is the whole point of this constant.
 *
 * `select("*")` is what would ship the gated half of a route to somebody who
 * has not paid for it, the moment a column is added back to the routes table by
 * anyone who has not read the paywall spec. Naming the columns means a new
 * column is invisible until somebody decides it should be public.
 */
const ROUTE_COLUMNS =
  "id, centre_id, name, geometry, estimated_minutes, distance_km, difficulty, " +
  "speed_profile, observation_zones, phases, is_free";

export function listRoutesByCentre(centreId: string): Promise<Cached<Route[]>> {
  return cachedFetch(`routes:${centreId}`, async () => {
    const { data, error } = await supabase
      .from("routes").select(ROUTE_COLUMNS).eq("centre_id", centreId).order("name");
    if (error) throw new Error(error.message);
    return data as unknown as Route[];
  });
}

/**
 * A route and its hazards.
 *
 * `hazards` comes back empty for a locked route — the policy refuses the rows
 * rather than erroring — so an empty list here means "not entitled, or genuinely
 * no hazards" and must never be read as proof of a safe route. The screens gate
 * on `is_free` and the entitlement store instead, which is unambiguous.
 */
export function getRoute(routeId: string): Promise<Cached<{ route: Route; hazards: Hazard[] }>> {
  return cachedFetch(`route:${routeId}`, async () => {
    const { data: route, error } = await supabase
      .from("routes").select(ROUTE_COLUMNS).eq("id", routeId).single();
    if (error) throw new Error(error.message);
    const { data: hazards, error: e2 } = await supabase
      .from("hazards").select("*").eq("route_id", routeId).order("id");
    if (e2) throw new Error(e2.message);
    return { route: route as unknown as Route, hazards: (hazards ?? []) as Hazard[] };
  });
}

/**
 * The turn-by-turn, or null if the server would not give it up.
 *
 * `maybeSingle` rather than `single`: a policy that refuses a row returns zero
 * rows, and `single` turns that into an error indistinguishable from a network
 * failure. Null is the honest answer, and it is deliberately not `[]` — a route
 * can legitimately have no steps, and a screen that cannot tell those apart
 * would navigate somebody around a route it never received directions for.
 */
export function getRouteSteps(routeId: string): Promise<Cached<NavStep[] | null>> {
  return cachedFetch(`route-steps:${routeId}`, async () => {
    const { data, error } = await supabase
      .from("route_details").select("steps").eq("route_id", routeId).maybeSingle();
    if (error) throw new Error(error.message);
    return data ? ((data.steps ?? []) as NavStep[]) : null;
  });
}
```

```ts
import type { Route } from "@/types/db";

/**
 * Who may drive what, as pure functions.
 *
 * Kept out of the store and out of the screens for the reason `homeView` and
 * `routeSummary` are: these are the rules that decide whether somebody gets
 * what they paid for, and they should be provable without mounting a screen,
 * faking a purchase, or reaching a network.
 */

/** What the client believes, including not yet knowing. */
export type EntitlementStatus = "active" | "lapsed" | "unknown";

/** What a device can have written down. Never "unknown" — that is not a fact. */
export type StoredStatus = "active" | "lapsed";

/**
 * The status to act on, given what the network said and what this device
 * already knew.
 *
 * The fallback exists because a test centre car park is a plausible place to
 * have no signal, and a paying learner standing in one must not be locked out
 * of the route they came to drive.
 *
 * A device with no mirror at all resolves to `lapsed` rather than `active`.
 * That is the safe direction and it costs nothing: a device that has never
 * resolved an entitlement has never cached a locked route's steps either, so
 * opening the gate would reveal nothing.
 */
export function resolveStatus(live: EntitlementStatus, mirrored: StoredStatus | null): EntitlementStatus {
  if (live !== "unknown") return live;
  return mirrored ?? "lapsed";
}

export function isEntitled(status: EntitlementStatus): boolean {
  return status === "active";
}

/**
 * The one question every screen asks.
 *
 * Takes the route rather than a route id so it cannot be called without the
 * `is_free` flag in hand — the flag travels on every row `listRoutesByCentre`
 * returns, so there is never a reason to fetch it separately.
 */
export function canDrive(route: Pick<Route, "is_free">, status: EntitlementStatus): boolean {
  return route.is_free || isEntitled(status);
}

/** How many of a centre's routes this person cannot open. */
export function lockedCount(routes: Pick<Route, "is_free">[], status: EntitlementStatus): number {
  return routes.filter((r) => !canDrive(r, status)).length;
}

/**
 * The first route this person could actually drive.
 *
 * Home and the result screen use it so that a recommendation never points at a
 * wall. Generic in its element type so a caller keeps whatever else its rows
 * carry — an id, a name — rather than getting back a bare `{ is_free }`.
 */
export function firstDrivable<T extends Pick<Route, "is_free">>(
  routes: T[], status: EntitlementStatus,
): T | null {
  return routes.find((r) => canDrive(r, status)) ?? null;
}
```

```ts
/**
 * Take every cached route off the device, because the subscription that paid
 * for them has ended.
 *
 * Without this the paywall has a hole with a clear shape: subscribe, open nine
 * centres so their routes and turn-by-turn land on disk, cancel, and keep
 * driving all of them offline for as long as the install lasts. The server
 * would refuse every one of those reads; nothing would ever ask it.
 *
 * One prefix covers all three shapes the routes repo writes — `cache:routes:`,
 * `cache:route:` and `cache:route-steps:` — because all three begin with
 * `cache:route`.
 *
 * Separate from `clearUserCache` rather than a flag on it, matching how
 * `clearOutbox` is separate: sign-out wants one of these, a lapse wants the
 * other, and a boolean argument would put that decision at the call site of a
 * function whose whole job is to not need one.
 */
export async function clearRouteCache(): Promise<void> {
  const keys = await AsyncStorage.getAllKeys();
  const routes = keys.filter((k) => k.startsWith("cache:route"));
  if (routes.length > 0) await AsyncStorage.multiRemove([...routes]);
}
```

```ts
import { create } from "zustand";
import AsyncStorage from "@react-native-async-storage/async-storage";
import { isEntitled, resolveStatus, type EntitlementStatus, type StoredStatus } from "@/lib/gating";
import { clearRouteCache } from "@/services/cache";
import * as purchases from "@/services/purchases";
import type { Entitlement, Plan } from "@/services/purchases";

/**
 * Whether this account has paid, and what the app does about it.
 *
 * The store never *decides* the answer — Postgres does, through the policies on
 * `route_details` and `hazards`. Everything here exists so the app can draw the
 * right thing before the server is asked, and so a learner with no signal is
 * not locked out of a route they are paying for.
 */

/**
 * The last answer this device got, so it can be honoured while offline.
 *
 * Only ever "active" or "lapsed": "unknown" is the absence of a fact, and
 * writing it down would make the fallback meaningless.
 */
export const MIRROR_KEY = "entitlement:last";

type EntitlementState = {
  status: EntitlementStatus;
  product: string | null;
  renewsAt: string | null;
  init: () => Promise<void>;
  refresh: () => Promise<void>;
  identify: (userId: string) => Promise<void>;
  purchase: (plan: Plan) => Promise<string | null>;
  restore: () => Promise<string | null>;
  reset: () => Promise<void>;
};

export function selectStatus(s: EntitlementState): EntitlementStatus {
  return s.status;
}

export function selectEntitled(s: EntitlementState): boolean {
  return isEntitled(s.status);
}

async function readMirror(): Promise<StoredStatus | null> {
  const raw = await AsyncStorage.getItem(MIRROR_KEY).catch(() => null);
  return raw === "active" || raw === "lapsed" ? raw : null;
}

export const useEntitlement = create<EntitlementState>((set, get) => {
  /**
   * Fold an answer into the store, and sweep if access was just lost.
   *
   * The sweep fires on the *transition* into lapsed rather than on the state,
   * for two reasons. A person who was already lapsed may still have the free
   * routes cached, and dropping those on every refresh would break offline
   * practice for somebody who never paid anything and never did anything wrong.
   * And an unresolved status must never sweep: that is the offline case, where
   * the mirror is the only thing keeping a paying learner in.
   */
  const apply = async (answer: Entitlement | null) => {
    const live: EntitlementStatus = answer === null ? "unknown" : answer.active ? "active" : "lapsed";
    const status = resolveStatus(live, await readMirror());
    const lost = get().status === "active" && status === "lapsed";

    set({
      status,
      product: answer?.product ?? (status === "active" ? get().product : null),
      renewsAt: answer?.renewsAt ?? (status === "active" ? get().renewsAt : null),
    });

    if (status !== "unknown") {
      await AsyncStorage.setItem(MIRROR_KEY, status).catch(() => { /* a full disk is not a reason to lock someone out */ });
    }
    if (lost) {
      await clearRouteCache().catch(() => { /* the server refuses these reads anyway */ });
    }
  };

  return {
    status: "unknown",
    product: null,
    renewsAt: null,

    init: async () => {
      try { await purchases.configure(); } catch { /* the fallback below covers it */ }
      await apply(await purchases.currentInfo().catch(() => null));
    },

    refresh: async () => {
      await apply(await purchases.currentInfo().catch(() => null));
    },

    /**
     * Tie the store account to this Supabase account.
     *
     * Called on every session open rather than only on sign-in: the id is what
     * the webhook keys the entitlements row on, and a session restored from disk
     * has never been through `signIn`.
     */
    identify: async (userId) => {
      await apply(await purchases.identify(userId).catch(() => null));
    },

    /**
     * Buy a plan. Null means nothing to say — which covers both success and a
     * cancelled sheet, exactly as `signInWithProvider` does, because in both
     * cases the screen has nothing to tell the person that the new state does
     * not already say.
     */
    purchase: async (plan) => {
      let answer: Entitlement | null;
      try {
        answer = await purchases.buy(plan);
      } catch {
        return "That didn't go through. Nothing has been charged.";
      }
      if (answer === null) return null; // cancelled
      await apply(answer);
      return null;
    },

    restore: async () => {
      let answer: Entitlement | null;
      try {
        answer = await purchases.restore();
      } catch {
        return "Couldn't reach the App Store. Try again in a moment.";
      }
      await apply(answer);
      if (!answer?.active) return "No subscription found on this Apple ID.";
      return null;
    },

    /**
     * Sign-out. The mirror goes with it — it is this device's memory of one
     * account's subscription, and the next person to sign in on this phone must
     * not inherit it.
     */
    reset: async () => {
      try { await purchases.signOutPurchases(); } catch { /* local teardown is what matters */ }
      await AsyncStorage.removeItem(MIRROR_KEY).catch(() => {});
      set({ status: "unknown", product: null, renewsAt: null });
    },
  };
});
```

```ts
import type { Plan } from "@/services/purchases";
import type { TestWindow } from "@/lib/onboarding";

/**
 * What the paywall says, as data rather than as JSX.
 *
 * Here for the reason `verifyCopy` and `homeView` are: this is the copy that
 * decides whether anybody pays, it should be arguable over in a test rather
 * than inside a bottom sheet, and it reads from the sign-up interview's answers
 * — which are the app's one piece of genuine knowledge about the person.
 */

const NUMBERS = ["", "One", "Two", "Three", "Four", "Five", "Six", "Seven", "Eight", "Nine"];

/**
 * "Nine more routes at Wood Green".
 *
 * Names the centre, because the sheet opens on somebody who was looking at that
 * centre's routes a moment ago. "Upgrade to Premium" describes what the company
 * wants; this describes what they were already trying to do.
 *
 * Past nine it switches to the numeral, matching `count` in routeSummary — the
 * same reason there: words read worse than digits once they get long.
 */
export function paywallHeadline(centreName: string, lockedCount: number): string {
  const n = lockedCount < 10 ? NUMBERS[lockedCount] : String(lockedCount);
  const noun = lockedCount === 1 ? "route" : "routes";
  if (!centreName) return `${n} more ${noun} to drive`;
  return `${n} more ${noun} at ${centreName}`;
}

/**
 * The plan shown selected when the sheet opens.
 *
 * Somebody testing inside a fortnight genuinely needs about a fortnight, and
 * showing them the monthly plan first asks them to buy three weeks they will
 * not use. Everybody else is better served by the cheaper-per-week option, which
 * is the monthly one.
 */
export function defaultPlan(window: TestWindow | null): Plan {
  return window === "two_weeks" ? "weekly" : "monthly";
}

/**
 * One sentence under the headline.
 *
 * Silent about dates for anybody who has not given one. "Not booked yet" was
 * written on a card that promised "No countdown, no nagging", and inventing
 * urgency for that person would break the promise the interview made.
 */
export function paywallReason(window: TestWindow | null): string {
  switch (window) {
    case "two_weeks":
      return "Your test is in under two weeks. Every route you drive is one fewer road the examiner can surprise you with.";
    case "this_month":
      return "Your test is this month. The examiner picks the route; you can know all of them first.";
    case "later":
      return "There is time to drive all of them before your test, a route at a time.";
    default:
      return "The examiner picks the route on the day. This is how you have already driven it.";
  }
}
```

- [ ] **Step 1: Write the function**

Create `supabase/functions/revenuecat-webhook/index.ts`:

```ts
// Writes the entitlements row, and is the only thing that may.
//
// The app never writes its own entitlement — an app that could would be an app
// that can grant itself a subscription. This runs under the service role, which
// bypasses RLS, which is exactly why the authorisation check below is the whole
// security of the paywall rather than a formality.
//
// Runs with verify_jwt = false (see supabase/config.toml). It has to: RevenueCat
// sends its own configured Authorization header, not a Supabase JWT. That is
// precisely why the shared-secret comparison is not optional — without it this
// is a public URL that grants subscriptions.
//
// Deploy:  npx supabase functions deploy revenuecat-webhook
//          npx supabase secrets set REVENUECAT_WEBHOOK_SECRET=<generated>

import { createClient } from "jsr:@supabase/supabase-js@2";

const CORS = {
  "Access-Control-Allow-Origin": "*",
  "Access-Control-Allow-Headers": "authorization, content-type",
};

const SECRET = Deno.env.get("REVENUECAT_WEBHOOK_SECRET") ?? "";

/**
 * Compared in constant time so the endpoint does not leak the secret one byte
 * at a time to anybody willing to measure how long it takes to say no.
 *
 * The length check first is not a leak worth caring about — the length of a
 * secret is not the secret — and it is what lets the loop below be a fixed
 * number of comparisons.
 */
function secretMatches(given: string): boolean {
  if (SECRET.length === 0 || given.length !== SECRET.length) return false;
  let diff = 0;
  for (let i = 0; i < SECRET.length; i++) diff |= given.charCodeAt(i) ^ SECRET.charCodeAt(i);
  return diff === 0;
}

const UUID = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

/**
 * What each event means for access — which is not the same as what it means for
 * billing, and the gap is where this would go wrong if it were written from the
 * event names alone.
 *
 * CANCELLATION maps to `active` on purpose. In Apple's vocabulary a
 * cancellation is auto-renew being switched off, not access ending: somebody
 * who cancels on day two of a month has twenty-eight days paid for. Taking the
 * routes away at CANCELLATION would be taking away something already bought.
 * EXPIRATION is the event that actually ends it.
 *
 * BILLING_ISSUE is the grace period — the card failed and Apple is retrying.
 * The person is still owed their routes while that plays out.
 */
const ACCESS: Record<string, "active" | "lapsed"> = {
  INITIAL_PURCHASE: "active",
  RENEWAL: "active",
  UNCANCELLATION: "active",
  PRODUCT_CHANGE: "active",
  SUBSCRIPTION_EXTENDED: "active",
  CANCELLATION: "active",
  BILLING_ISSUE: "active",
  EXPIRATION: "lapsed",
};

Deno.serve(async (req) => {
  if (req.method === "OPTIONS") return new Response("ok", { headers: CORS });

  if (!secretMatches(req.headers.get("Authorization") ?? "")) {
    return new Response("unauthorized", { status: 401, headers: CORS });
  }

  let event: Record<string, unknown>;
  try {
    const body = await req.json();
    event = (body.event ?? {}) as Record<string, unknown>;
  } catch {
    return new Response("bad request", { status: 400, headers: CORS });
  }

  const type = String(event.type ?? "");
  const userId = String(event.app_user_id ?? "");
  const status = ACCESS[type];

  // 200 rather than 4xx for everything understood-but-ignored. A non-200 makes
  // RevenueCat retry, and retrying an event we have decided to drop just means
  // dropping it repeatedly. TRANSFER and TEST land here.
  if (!status) return new Response("ignored", { status: 200, headers: CORS });

  // A row keyed on nonsense is worse than no row: it is invisible and it never
  // matches anybody. This fires if Purchases.logIn was never called with the
  // Supabase id, which is the one wiring mistake this whole design can make.
  if (!UUID.test(userId)) {
    console.error(`[revenuecat] app_user_id is not a uuid: ${userId} (event ${type})`);
    return new Response("ignored", { status: 200, headers: CORS });
  }

  const supabase = createClient(
    Deno.env.get("SUPABASE_URL")!,
    Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")!,
  );

  const eventAt = new Date(Number(event.event_timestamp_ms ?? Date.now()));

  /**
   * Webhooks arrive out of order, and the damage is asymmetric: a late
   * EXPIRATION landing after a fresh RENEWAL would cancel a subscription that
   * is very much alive, and the person would have no way to tell us.
   *
   * So the row's own `updated_at` is the clock. An event older than what is
   * already recorded is dropped, and dropping a stale one costs nothing — the
   * newer event it lost a race to already said everything true.
   */
  const { data: existing } = await supabase
    .from("entitlements").select("updated_at").eq("user_id", userId).maybeSingle();

  if (existing && new Date(existing.updated_at) > eventAt) {
    console.log(`[revenuecat] dropping stale ${type} for ${userId}`);
    return new Response("stale", { status: 200, headers: CORS });
  }

  const { error } = await supabase.from("entitlements").upsert({
    user_id: userId,
    status,
    product: (event.product_id as string | null) ?? null,
    renews_at: event.expiration_at_ms ? new Date(Number(event.expiration_at_ms)).toISOString() : null,
    updated_at: eventAt.toISOString(),
  }, { onConflict: "user_id" });

  if (error) {
    // 500 so RevenueCat retries — this one is worth retrying, because the event
    // was valid and the write is what failed.
    console.error(`[revenuecat] upsert failed for ${userId}: ${error.message}`);
    return new Response("write failed", { status: 500, headers: CORS });
  }

  return new Response("ok", { status: 200, headers: CORS });
});
```
