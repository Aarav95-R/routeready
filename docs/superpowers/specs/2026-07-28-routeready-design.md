# RouteReady — Design Spec

**Date:** 2026-07-28
**Status:** Approved pending user review
**Platform:** iOS-only, Expo SDK 52+, must run in Expo Go during development. Release target: iOS App Store.

## 1. Product summary

RouteReady lets UK learner drivers (17–25) practice official DVSA driving test routes: browse test centres, drive seeded routes with voice guidance (Practice Mode), take silently-scored mock tests (Mock Test Mode), train manoeuvres, quiz Show Me/Tell Me questions, and track progress.

## 2. Decisions locked with the user

| Decision | Choice |
|---|---|
| Backend | Real Supabase — user creates the project and supplies URL + anon key; app requires credentials to run |
| Auth gating | Required login at launch (email/password + magic link) |
| Phasing | Phase 1: foundation, auth, centres, routes, practice + mock test. User reviews in Expo Go. Phase 2: manoeuvre trainer, dashboard, quiz, polish |
| Seed data | Road-snapped route geometry generated by a one-off Node script calling the public OSRM API; output committed as static SQL. App never calls OSRM |
| Mock scoring | DVSA fault model: ≤15 minors = pass, any serious/dangerous = fail. Sustained speeding rule. Tap-the-Mirrors observation zones |

## 3. Tech stack

- **Framework:** Expo SDK 52+, TypeScript (strict), Expo Router v3 (file-based, `/app`)
- **Maps:** `react-native-maps`, Apple Maps default provider, `mapType="mutedStandard"`
- **Styling:** NativeWind (Tailwind for RN)
- **State:** Zustand
- **Storage:** `@react-native-async-storage/async-storage` (cache, queued writes), `expo-secure-store` (Supabase session tokens)
- **Animations:** `react-native-reanimated` v3; **Bottom sheet:** `@gorhom/bottom-sheet` (snap points 25/50/90%, handle `#CBD5E1`)
- **Voice:** `expo-speech`; **Location:** `expo-location`; **Haptics:** `expo-haptics`; **Connectivity:** `@react-native-community/netinfo`
- **Icons:** `@expo/vector-icons` (Ionicons + FontAwesome6); **Charts:** `react-native-gifted-charts`; **Fonts:** Inter via `expo-font` `useFonts`
- **Backend:** Supabase (Postgres + RLS, Auth, Storage). No Edge Functions in MVP.

All libraries have pre-built native modules compatible with Expo Go.

## 4. Architecture

Three layers, strictly separated:

### 4.1 Services (`src/services/`)
Repositories: `centresRepo`, `routesRepo`, `progressRepo`, `quizRepo`, `manoeuvresRepo`, `favouritesRepo`.

- Reads: Supabase → write-through to AsyncStorage → on network failure serve cached copy with a `stale: true` flag (UI shows the offline banner).
- Writes (progress, favourites): attempt Supabase; on failure enqueue in an AsyncStorage outbox, flushed by a NetInfo listener when connectivity returns.
- Screens and stores never import the Supabase client directly.

### 4.2 Stores (`src/stores/`)
Zustand stores: `sessionStore` (auth state, hydrated from secure store), one store per domain, and `mockTestStore` — the live mock-test state machine (recording GPS samples, faults, zone state).

### 4.3 Screens (`app/`)
- `(auth)/sign-in`, `(auth)/sign-up` — auth wall. Root layout redirects here when no session. Magic link handled via `expo-linking` deep link → `supabase.auth` session exchange.
- `(tabs)/index` (Centres), `(tabs)/progress`, `(tabs)/manoeuvres`, `(tabs)/quiz`
- `centre/[id]` — centre detail
- `route/[id]` — route detail; `route/[id]/practice`; `route/[id]/mock`; `route/[id]/result`

Native stack transitions; shared-element transition route card → detail (Phase 2 polish if it risks Phase 1 timeline).

## 5. Data model

User-provided schema (test_centres, routes, hazards, user_progress, manoeuvres, show_me_tell_me + RLS policies) stands as written, with four deltas:

1. `routes.speed_profile jsonb` — array of `{ startIdx, endIdx, limitMph }` segments over the LineString coordinates. Derived at seed time from OSRM speed annotations banded to UK limits (20/30/40/60/70 mph, urban default 30).
2. `routes.observation_zones jsonb` — array of `{ lat, lng, radiusM, kind }` (`roundabout` | `junction` | `pedestrian`) where the mock test expects a mirror-check tap.
3. New table `favourites (id uuid pk, user_id uuid references auth.users on delete cascade, route_id uuid references routes on delete cascade, created_at timestamptz default now(), unique(user_id, route_id))` with RLS `for all to authenticated using (auth.uid() = user_id) with check (auth.uid() = user_id)`.
4. `test_centres.pass_rate_history jsonb` (default `'[]'`) — 8 quarterly pass-rate values, generated deterministically at seed time, feeding the centre-detail sparkline.

Voice turn-by-turn instructions are **not** stored in the DB: they are derived client-side at route load from the LineString geometry (bearing changes) by `src/lib/instructions.ts`, keeping the schema lean and instructions tunable without a reseed.

RLS note: since login is required, public-read policies may be restricted to `authenticated` only; keep `anon` read anyway so the app can render marketing/preview states cheaply — no harm, data is non-sensitive.

## 6. Seed pipeline (`scripts/seed/`, Node + TypeScript, run once locally)

1. `centres.json` — 40 real DVSA test centres (real names, addresses, coordinates; realistic pass rates ~40–60%), spread across UK regions.
2. Per centre, 3–4 waypoint sets radiating into surrounding roads → public OSRM API (`router.project-osrm.org`, `overview=full`, `annotations=speed`) → road-following GeoJSON LineStrings + distance/duration. Rate-limited politely (sequential, delay between calls).
3. Derivations: difficulty 1–5 from junction density + bearing-change count; hazard pins at detected sharp turns/roundabout-like loops plus curated descriptions; speed bands from OSRM speed annotations.
4. Output: `supabase/schema.sql` (user schema + deltas) and `supabase/seed.sql` — user pastes both into the Supabase SQL Editor.
5. Show Me/Tell Me: 18 real DVSA questions seeded across categories (under bonnet / inside car / safety). Manoeuvres: 4 (parallel park, bay park, pull up on the right, forward bay park) with step arrays and tips.

## 7. Feature designs

### 7.1 Test Centre Directory (Phase 1)
Searchable FlatList of centres. Card: name, pass rate, distance from user (via `expo-location` last known position), route count. Filters: nearest / highest pass rate / manual-auto. Pull-to-refresh. Skeleton placeholders while loading. Offline: cached list + subtle banner. Centre detail: address, pass-rate sparkline (gifted-charts), route list, "Start Practice" CTA.

### 7.2 Route System (Phase 1)
Route detail: mini-map preview, estimated time, distance, difficulty (1–5 pips), hazard preview list. Swipe right on route card = Start (green reveal), swipe left = Favourite (amber star).

**Practice Mode:** full-screen Apple Maps (mutedStandard), user location dot, polyline `#059669` 5px rounded caps, hazard pins `#D97706` opening a bottom sheet with instructor tips. Turn-by-turn voice via `expo-speech`, instructions precomputed at seed time from geometry bearing changes ("In 200 yards, at the roundabout, take the second exit"), triggered by proximity to instruction points.

**Mock Test Mode:** silent GPS tracking (`expo-location` `bestForNavigation`). Scoring engine = pure functions over GPS samples:
- *Speeding:* GPS speed vs. matched segment limit. Exceeding limit + 10% + 2 mph sustained ≥5 s = serious fault; brief exceedance = minor. Sustained filter kills GPS noise.
- *Observations:* entering an observation zone pulses a "Mirrors" button; tap inside the zone = check logged, miss = minor fault tagged by zone kind (feeds weakness tags).
- Result: DVSA model, ≤15 minors and no serious = pass. Animated pass/fail reveal + breakdown cards. Saved to `user_progress` (score, mistakes tags, duration); offline results queue and sync.

### 7.3 Manoeuvre Trainer (Phase 2)
4 manoeuvres. Step-by-step guide with sequenced Reanimated SVG diagrams. Checklist mode: tap observations, light haptic per tick.

### 7.4 Progress Dashboard (Phase 2)
Stats tiles (practice hours, routes completed, average mock score), score trend line (gifted-charts), weakness tags aggregated from `user_progress.mistakes`, test-date countdown, practice streak.

### 7.5 Show Me / Tell Me (Phase 2)
18-question seeded bank, categorised. Random quiz with reveal-answer flow, success/error haptics.

## 8. Design system

- **Colours:** Primary `#0F172A`, Accent `#059669` (pressed `#047857`), Warning `#D97706`, Surface `#F8FAFC`, Card `#FFFFFF`, Danger `#DC2626`.
- **Type:** Inter — headings semibold, tracking -0.02em; body regular, relaxed leading.
- **Shape:** 12px card radius, 9999px pills/CTAs, 8px inputs. 4px spacing grid, 16px horizontal margins. Subtle iOS shadows (`shadow-slate-900/10`).
- **Interaction:** buttons scale 0.97 on press; haptics on route start, checklist tick, pass/fail reveal, quiz answer; 44×44pt minimum touch targets; safe areas everywhere; status bar style per screen luminance; dark-mode: keep map muted, darken overlay UI.

## 9. Error handling & offline

- No blank screens: skeletons for loading, inline error states with retry for failures.
- NetInfo-driven offline banner; reads fall back to cache; writes queue in outbox.
- Auth errors (bad credentials, expired magic link) surface inline on the auth screens.
- GPS permission denied → practice/mock screens show an explanatory state with a Settings link; app remains browsable.

## 10. Testing

- Scoring engine: pure-function unit tests (jest-expo) — synthetic GPS traces in, expected faults out (speeding sustained vs. brief, zone hit/miss).
- Repositories: unit tests with mocked Supabase client + AsyncStorage (cache fallback, outbox flush).
- Stores: unit tests for mock-test state machine transitions.
- Maps, GPS, voice, haptics: manual QA in Expo Go on device (Phase 1 review checkpoint).

## 11. Out of scope (MVP)

Instructor realtime tracking, Supabase Edge Functions, Android, route illustration images in Supabase Storage, anonymous browsing mode.
